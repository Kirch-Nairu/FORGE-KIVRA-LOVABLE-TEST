# LOVABLE CREDIT-EFFICIENCY DIRECTIVE

## Objective

Use Lovable build credits for implementation, not discovery or repeated self-review.

## Rules

1. Read authority in read-only mode first.
2. No exploratory code generation.
3. No tests generated by Lovable:
   - no Vitest/Jest;
   - no Playwright/Cypress;
   - no E2E;
   - no test snapshots;
   - no CI workflows.
4. No backend or Cloud setup.
5. No dependency shopping.
6. Prefer one broad implementation pass over dozens of micro-prompts.
7. Do not rewrite authority docs.
8. Do not ask Lovable for a second broad self-audit after completion.
9. Fix only compile/runtime blockers necessary to leave preview working.
10. Stop when authorized scope is implemented.

## Dependency posture

Use current Lovable defaults.

Only add a package when it materially reduces implementation complexity.

Acceptable if genuinely needed:
- lightweight state library;
- icon library already used by template;
- existing chart library;
- date utilities.

Avoid:
- auth/backend SDKs;
- analytics;
- AI clients;
- payment clients;
- huge PDF engines solely for a demo;
- animation frameworks solely for decoration.

## Report, don't rework

At completion return:
- files changed;
- routes implemented;
- dependencies added;
- simulated features;
- unimplemented features;
- build/preview status;
- known limitations.

Forge reviews externally.
